# Yuwell PAP Logger

เก็บข้อมูลการนอนจากเครื่อง CPAP/APAP **Yuwell YH550 (BreathCare ECO)** ไว้ระยะยาว

เครื่องเขียน session ลง SD card เป็นไฟล์ `.BYS` และการ์ดมีพื้นที่จำกัด — ข้อมูลจะหายเมื่อการ์ดเต็ม
หรือถูกรีเซ็ต โปรเจกต์นี้อ่านไฟล์เหล่านั้นผ่านหน้าเว็บ แปลงเป็น time series แล้วเก็บลง InfluxDB
แบบไม่มีวันหมดอายุ เพื่อให้ดูแนวโน้ม AHI / แรงดัน / การรั่วของหน้ากาก ย้อนหลังได้เป็นปี ๆ

> ## ⚠️ ห้ามใช้เพื่อการวินิจฉัยทางการแพทย์
>
> เครื่องมือนี้แสดงตัวเลขที่อ่านได้จากไฟล์ของเครื่องเท่านั้น **ไม่ใช่อุปกรณ์การแพทย์**
> และรูปแบบไฟล์มาจากการ reverse engineering ไม่ใช่สเปกทางการจากผู้ผลิต — ประมาณ 19%
> ของข้อมูลในไฟล์ยังไม่ทราบความหมาย ห้ามใช้ตัดสินใจเรื่องการรักษาโดยไม่ปรึกษาแพทย์

## รุ่นที่รองรับ

**YH550 (BreathCare ECO, A/B models) เท่านั้น**

รุ่นอื่น (YH580, YH830, YH680/YH690) ใช้รูปแบบไฟล์คนละแบบและ**ยังไม่รองรับ** — โครงสร้าง
`app/parsers/` เปิดทางให้เพิ่มได้ แต่ยังไม่มีข้อมูลทดสอบ ระบบจะปฏิเสธไฟล์ที่ไม่ตรงโครงสร้าง YH550
แทนที่จะเดาแล้วเขียนตัวเลขผิดลงฐานข้อมูล

## เริ่มใช้งาน

ต้องมี Docker และ Docker Compose

```bash
cp .env.example .env
$EDITOR .env
```

**ก่อนสั่ง `docker compose up` ต้องสร้าง `SECRET_KEY` ก่อน** — ค่านี้ใช้เซ็น session cookie
ถ้าเป็นค่าที่อยู่ใน repo สาธารณะ (ว่าง หรือ placeholder เดิม) ใครก็เดา/อ่านค่านั้นแล้วปลอม cookie
เป็นผู้ใช้คนอื่นเพื่ออ่านข้อมูลสุขภาพได้ทันที — เพราะแบบนั้น**ไม่ตั้งค่านี้ = `docker compose up`
ไม่ขึ้นเลย** และถ้าใส่ค่า placeholder เดิมเข้าไปตรง ๆ **แอปก็จะปฏิเสธไม่สตาร์ตเช่นกัน**

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

คัดลอกผลลัพธ์ไปใส่ `SECRET_KEY=` ใน `.env` แล้วแก้ `INFLUX_TOKEN` กับรหัสผ่านอื่น ๆ ต่อ และ
**ตั้งบัญชีแรกตรงนี้เลย**:

```bash
INIT_USERNAME=ชื่อที่ใช้ล็อกอิน
INIT_PASSWORD=รหัสผ่านอย่างน้อย8ตัว
```

> **เปลี่ยน `SECRET_KEY` ทีหลัง = ทุกคนถูก logout ทันที** เพราะ session cookie ที่เซ็นด้วยคีย์เก่า
> จะตรวจสอบไม่ผ่านอีกต่อไป ตั้งครั้งเดียวให้เรียบร้อยแล้วอย่าสุ่มใหม่โดยไม่จำเป็น

```bash
docker compose --profile local-influx up -d
```

เปิด <http://localhost:8000> ล็อกอินด้วยค่าที่ตั้งไว้ แล้วอัปโหลดไฟล์ได้เลย

> **`INIT_*` ใช้ตอน initialise เท่านั้น** — อ่านเฉพาะตอนที่ระบบยังไม่มีบัญชีใด ๆ
> แก้ `INIT_PASSWORD` ทีหลังแล้วรีสตาร์ต **รหัสจะไม่เปลี่ยน** (แอปจะเตือนใน log ให้ถ้าค่าไม่ตรงกันแล้ว)
> เปลี่ยนรหัสด้วย `docker compose exec app python -m app.cli passwd <ชื่อ>`
>
> **แนะนำให้เก็บสองบรรทัดนี้ไว้ใน `.env`** ถ้าวันหนึ่ง volume ของฐานข้อมูลหายไปจนไม่เหลือบัญชี
> ขณะที่ InfluxDB ยังเก็บข้อมูลสุขภาพของคุณอยู่ครบ แอปจะสร้างบัญชีเดิมกลับมาให้เอง
> แทนที่จะเปิดหน้าสร้างบัญชีทิ้งไว้ให้ใครก็ได้ที่เข้าถึงพอร์ตมายึดเป็นผู้ดูแลระบบ

### ถ้าไม่อยากใส่รหัสผ่านใน `.env`

เว้น `INIT_USERNAME`/`INIT_PASSWORD` ว่างไว้ แอปจะสุ่ม **setup token** ให้แทน แล้วไปสร้างบัญชีเองที่ `/setup`

```bash
docker compose exec app cat /srv/data/setup-token
```

token ยังพิมพ์อยู่ใน log ตอนสตาร์ตด้วย **ค่าไม่เปลี่ยนเวลารีสตาร์ต** และถูกลบทิ้งทันทีที่สร้างบัญชีแรกสำเร็จ

> **ทำไมต้องมี token:** ระหว่างที่ระบบยังไม่มีบัญชี ใครก็ตามที่เข้าถึงพอร์ตได้คือคนที่จะได้เป็นผู้ดูแลระบบ
> การบังคับให้กรอกค่าที่อยู่บนเครื่องเซิร์ฟเวอร์เท่านั้น ทำให้คนที่เข้าถึงเครื่องได้เท่านั้นที่ยึดระบบได้

| บริการ | ที่อยู่ |
|---|---|
| หน้าอัปโหลด / รายการ session | <http://localhost:8000> |
| Grafana (กราฟทั้งหมด) | <http://localhost:3000> |
| InfluxDB UI | <http://localhost:8086> |

### อัปโหลดข้อมูล

ถอด SD card จากเครื่องมาเสียบคอมพิวเตอร์ แล้วเลือกวิธีใดวิธีหนึ่ง:

1. **zip ทั้งโฟลเดอร์แล้วอัปไฟล์เดียว** — วิธีที่แนะนำเมื่อมีไฟล์เยอะ (800 ไฟล์ zip แล้วเหลือ ~340 KB)
2. **เลือกทั้งโฟลเดอร์** ผ่านปุ่มเลือกโฟลเดอร์บนหน้าเว็บ
3. **ลากไฟล์หลาย ๆ ไฟล์** ลงในหน้าเว็บ

อัปไฟล์เดิมซ้ำได้เสมอ ระบบเทียบด้วย SHA-256 ของเนื้อไฟล์ แล้วข้ามไฟล์ที่เคยนำเข้าแล้ว
ถ้าอัปโหลดขาดกลางคัน ให้อัปใหม่ทั้งชุดได้เลย — จะทำต่อจากเดิมเอง

## การตั้งค่า

ค่าทั้งหมดอยู่ใน `.env` ดูรายการเต็มพร้อมคำอธิบายใน [`.env.example`](.env.example)

ค่าที่สำคัญที่สุด:

| ตัวแปร | ความหมาย |
|---|---|
| `SECRET_KEY` | ใช้เซ็น session cookie เปลี่ยนแล้วทุกคนถูก logout |
| `DEVICE_TZ` | timezone ของ **เครื่อง CPAP** ไม่ใช่ของ server — ดูหัวข้อถัดไป |
| `DATABASE_URL` | ที่เก็บ users/devices/ประวัตินำเข้า ค่าเริ่มต้นเป็น SQLite |
| `INFLUX_URL` `INFLUX_TOKEN` `INFLUX_ORG` `INFLUX_BUCKET` | ที่เก็บ time series |

### ใช้ InfluxDB ตัวนอกแทนตัวใน Compose

ตัว InfluxDB ใน `docker-compose.yml` อยู่ใน profile `local-influx` — ถ้าไม่ระบุ profile จะไม่ถูกสร้าง
ดังนั้นการย้ายไปใช้ InfluxDB ตัวอื่น (เครื่องอื่นในบ้าน, ตัวที่คู่กับ Home Assistant, หรือ InfluxDB Cloud)
คือแก้ `.env` แล้วรันโดยไม่ใส่ profile:

```bash
# .env
INFLUX_URL=https://influx.example.lan:8086
INFLUX_TOKEN=...
INFLUX_ORG=...
INFLUX_BUCKET=...
```

```bash
docker compose up -d          # ไม่มี --profile local-influx = ไม่สร้าง Influx ตัวใน compose
```

หน้า `/health` จะบอกว่าตอนนี้ต่ออยู่กับ Influx ตัวไหนและเขียนได้จริงหรือไม่

> **retention ของ bucket ต้องเป็น infinite** เป้าหมายทั้งโปรเจกต์คือเก็บถาวร ถ้าคุณสร้าง bucket
> เองบน Influx ตัวนอก อย่าลืมตั้ง retention เป็น "never" — ข้อมูลกินพื้นที่ประมาณ 200,000
> point ต่อปีต่อผู้ใช้ ซึ่งเล็กมาก

### timezone

ไฟล์ `.BYS` เก็บเวลาแบบ **local wall-clock ไม่มีข้อมูล timezone ติดมาด้วย** ระบบใช้ `DEVICE_TZ`
แปลงเป็น UTC ก่อนเขียนลง InfluxDB ถ้าตั้งผิด กราฟจะเลื่อนไปทั้งแถบ

session ที่เริ่มหลังเที่ยงคืนจะถูกนับเป็น "คืนของวันก่อนหน้า" (เริ่มนอนตี 0:42 ของวันที่ 22
= คืนวันที่ 21) เพื่อให้การนับรายคืนตรงกับความรู้สึกของคนใช้

## การแบ่งผู้ใช้ — ข้อจำกัดที่ต้องรู้

หน้าเว็บของแอป (`/`, `/sessions`) **แยกผู้ใช้จริง**: ทุก query กรองด้วยบัญชีที่ล็อกอินอยู่
และเครื่องแต่ละเครื่อง (ระบุด้วย serial) ผูกกับเจ้าของคนแรกที่อัปโหลด คนอื่นอัปไฟล์จากเครื่องนั้นไม่ได้

> ### ⚠️ Grafana ไม่ได้แยกผู้ใช้ให้
>
> Grafana เป็นคนละแอปและมีระบบล็อกอินของตัวเอง **การแบ่งผู้ใช้ของแอปนี้ไม่มีผลกับ Grafana เลย**
> dashboard ใช้ตัวแปร `$user` เพื่อความสะดวกในการสลับดู — **ไม่ใช่ขอบเขตความปลอดภัย**
> ใครก็ตามที่เข้า Grafana ได้ สามารถเลือกดูข้อมูลของผู้ใช้คนอื่นได้ทั้งหมด
>
> เหมาะกับการใช้ในครอบครัวที่ไว้ใจกัน **ไม่เหมาะกับการให้คนที่ไม่รู้จักกันใช้ร่วมกัน**
> ถ้าต้องการแยกจริง ต้องแยก bucket ต่อผู้ใช้ และแยก organization/datasource ใน Grafana
>
> ถ้าคุณต้องการเปิดให้เข้าจากภายนอก ให้ปิด Grafana ไว้หลัง reverse proxy ที่มี TLS
> และอย่าเปิดพอร์ต InfluxDB ตรง ๆ ออกอินเทอร์เน็ต

## รูปแบบไฟล์ YH550

โครงสร้าง: header 51 ไบต์ + record 10 ไบต์ × N + footer 1 ไบต์ (`0xFA`)
จึงได้ `len(file) == 51 + record_count × 10 + 1` — ยืนยันแล้วกับไฟล์จริง 46 ไฟล์
little-endian, ค่าทศนิยมเก็บเป็นจำนวนเต็ม × 10, ปีเป็นเลข 2 หลัก

ตาราง offset ฉบับเต็มอยู่ใน docstring ของ [`app/parsers/yh550.py`](app/parsers/yh550.py)
ซึ่งเป็นแหล่งอ้างอิงเดียวของโปรเจกต์ (เอกสารอื่นชี้มาที่นี่ ไม่คัดลอกตัวเลขไปวางซ้ำ)

**ไบต์ที่ยังไม่ทราบความหมาย** (byte 1, 2, 6, 7, 8 ของแต่ละ record) ถูกเก็บลงฐานข้อมูลด้วย
ไม่ได้ทิ้ง — วันหนึ่งถ้าถอดรหัสได้ จะย้อนอ่านจากข้อมูลที่เก็บไว้แล้วโดยไม่ต้องขอให้ผู้ใช้นำเข้าใหม่

**session ที่เครื่องเขียนไม่จบ** (ไฟดับ ถอดการ์ดขณะทำงาน) จะมี header ประกาศจำนวน record เต็ม
แต่ส่วนท้ายเป็น flash ที่ยังไม่ถูกเขียน (`0xFF` ล้วน) ซึ่งถ้าอ่านตรง ๆ จะกลายเป็น 25.5 cmH₂O
และ 255 event ต่อนาที ระบบจะตัดส่วนนั้นทิ้งพร้อมขึ้นเครื่องหมาย ⚠ ในหน้ารายการ session
ช่วง `0xFF` ที่อยู่กลางไฟล์**จะไม่ถูกตัด** เพราะนั่นไม่ใช่อาการเขียนไม่จบ และการซ่อนมันอันตรายกว่า
